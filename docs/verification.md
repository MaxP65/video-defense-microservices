# Проверка промежуточной версии: 8 ноября 2026

SHA256 Python-исходников версии обучения проверен по манифестам обоих окончательных запусков. Последующее уточнение подсчёта успеха adaptive-атаки меняет только отчёт инференса, не обучение и веса. Веса, полные split-манифесты, конфигурации, seed и история loss сохранены в локальном Storage и `artifacts/*-run.json`. Сводные карточки: [runs/local.md](experiments/runs/local.md).

Окружение: Windows, Python 3.12.11, PyTorch 2.4.1+cu121, CUDA, FastAPI 0.124.4, OpenCV 4.13.0, httpx 0.28.1. Первоначальная проверка относилась к локальному GPU-запуску; последующая CPU-проверка контейнеров описана отдельно в [docker-verification.md](docker-verification.md).

Данные: 72 реальных видео UCF101, три класса, seed 42; 36 train, 18 validation, 18 test. Группы и SHA256 файлов между split не пересекаются. Test не использован. По 40 эпох классификатора и очистителя; контроль MSE×0: ещё 40 эпох и 240 шагов с тем же seed и порядком батчей.

| Протокол validation | Правильные / всего | Точность |
|---|---:|---:|
| Исходные клипы | 10/18 | 55.56% |
| FGSM против классификатора | 5/18 | 27.78% |
| Очистка тех же FGSM-примеров | 7/18 | 38.89% |
| Очистка исходных клипов | 12/18 | 66.67% |
| Контроль с MSE×0 после FGSM | 5/18 | 27.78% |

PSNR по общей MSE validation увеличился с 30.43 до 31.98 дБ. MSE уменьшился с 0.00090528 до 0.00063437. Ошибка межкадровых разностей: 0.00081208 → 0.00079187. Необработанный и взвешенный MSE совпадают при весе 1. Конечные ненулевые validation-градиенты зарегистрированы для всех параметров полной модели; у контроля вес и градиенты равны нулю. Диагностика обучения очистителя: passed.

У классификатора повторение первого кадра даёт 13/18, обращение времени — 10/18. Преимущество использования движения не установлено; этот маленький классификатор может опираться на внешность и фон.

Отдельный технический пример `v_ApplyEyeMakeup_g25_c01.avi`, validation, epsilon=8/255: classifier-only FGSM меняет правильный ApplyEyeMakeup на BasketballDunk, очиститель восстанавливает ApplyEyeMakeup. Adaptive FGSM через всю цепочку на том же клипе сохраняет ошибку BasketballDunk после очистки: защита не выдержала этот пример, 0/1 правильных после adaptive-очистки. Это разные протоколы; один клип не является оценкой устойчивости на наборе.

Обе атаки: один вычисленный шаг FGSM, EOT=1, voting=1, один запуск без restarts. Число итераций — фактически выполненные шаги, а не время до первого успеха. Время отдельных примеров и полная длительность обучения записаны в карточках. Все перечисленные проверки завершены; массовые robustness/transfer sweep не запускались.

Проверки кода: 4/4 pytest, ruff без ошибок, Compose config проходит. Через реальный HTTP проверены пять сервисов, повторный импорт (0 новых видео), неверный split (422), обучение, обычная и adaptive-атаки. В браузере проверены выбор видео и отображение трёх вариантов с предсказаниями. На момент первоначальной проверки Docker engine был выключен. Позднее образы собраны и все пять контейнеров проверены; результаты приведены отдельно в [docker-verification.md](docker-verification.md).
